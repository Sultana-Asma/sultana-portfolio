Two Important Code Snippets & Technical Justification

// 1. Move raindrops down with natural wind drift
d.y += d.speed;
d.x += d.wind;

// 2. River surface collision: generate water ripple
if (d.y > height * 0.67 && Math.random() < 0.18) {
  addRipple(d.x, d.y); // Creates expanding water ring
}
if (d.y > height + 20) {
  d.y = -d.length; d.x = Math.random() * width;
}

Technical Justification: Procedural 2D Canvas rendering animates dynamic rain and water ripples in real-time within the browser DOM, eliminating the need for heavy static video files while recreating our desktop OpenGL simulation.

// 1. Hidden input: invisible to real users
<div className="hidden" aria-hidden="true">
  <input name="website" tabIndex={-1} autoComplete="off" ... />
</div>

// 2. Honeypot check in handleSubmit:
if (formData.website && formData.website.trim() !== "") {
  setStatus("success"); // Return dummy success
  return; // Silently discard automated spam submission
}

Technical Justification: An invisible input field hidden from human view (aria-hidden="true", tabIndex={-1}). Automated spam bots scrape the DOM and indiscriminately fill every field. If populated on submit, the script silently drops the submission without sending spam, providing frictionless protection without annoying CAPTCHAs.

07 // Problem Solving

Real Challenges Faced & Engineering Solutions

Slide 08 / 10

⚙️ 1. Desktop C++ OpenGL on Web

The Challenge: Our university graphics project was compiled as a native desktop C++ binary (.exe), making it impossible to run directly in web browsers.

Engineering Solution: Designed an interactive Case Study modal powered by an HTML5 Canvas simulation that recreates the Daytime, Night, and Rain visual dynamics directly inside the browser.

🎨 2. Modal Backdrop Transparency

The Challenge: The case study modal initially used a semi-transparent glass backdrop, causing background page text to bleed through and severely hurt readability.

Engineering Solution: Replaced the transparent background with a solid opaque charcoal slate surface (#0c101d) and a dark blur overlay (rgba(3, 7, 18, 0.85)) for 100% crisp text readability.

📱 3. Small-Screen Viewport Fit

The Challenge: On narrow mobile screens (320px–375px), skill progress bars, modal buttons, and text cards suffered layout squeezing and horizontal overflow.

Engineering Solution: Implemented responsive Flexbox wrapping, percentage-based grid columns, and CSS clamp() fluid typography to guarantee seamless multi-device scaling.
